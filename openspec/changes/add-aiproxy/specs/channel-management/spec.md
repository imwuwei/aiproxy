## ADDED Requirements

### Requirement: 渠道增删改查

系统 SHALL 提供渠道的创建、读取、更新、删除（CRUD）能力。渠道包含以下字段：名称、厂商类型（openai-compatible / anthropic / gemini / custom）、Base URL、API Key 列表（支持多个）、优先级（数值越小越优先）、启用状态、备注。

#### Scenario: 创建新渠道

- **WHEN** 用户填写渠道信息并提交保存
- **THEN** 渠道被持久化到数据库，并在渠道列表中可见

#### Scenario: 编辑渠道信息

- **WHEN** 用户修改渠道的 Base URL 或 API Key 并保存
- **THEN** 渠道信息被更新，后续代理请求使用更新后的配置

#### Scenario: 删除渠道

- **WHEN** 用户删除一个渠道
- **THEN** 该渠道及其渠道-模型映射记录被移除，不再参与代理路由

### Requirement: 渠道启停控制

系统 SHALL 支持对渠道进行启用/停用切换。停用的渠道 MUST NOT 参与模型同步与请求路由。

#### Scenario: 停用渠道

- **WHEN** 用户停用一个渠道
- **THEN** 该渠道不再出现在可路由列表中，已停用渠道上的请求将转移到其他可用渠道

#### Scenario: 启用渠道

- **WHEN** 用户重新启用一个已停用渠道
- **THEN** 该渠道恢复参与模型同步与请求路由

### Requirement: 渠道优先级排序

系统 SHALL 使用优先级字段对同一模型可用渠道进行排序。优先级数值越小，路由时优先选择。同等优先级下 SHALL 按渠道 ID 升序稳定选择。

#### Scenario: 按优先级选择渠道

- **WHEN** 多个启用渠道同时提供同一模型
- **THEN** 请求优先被发送到优先级数值最小的渠道

#### Scenario: 相同优先级处理

- **WHEN** 两个启用渠道提供同一模型且优先级相同
- **THEN** 系统按渠道 ID 升序稳定选择其一作为优先渠道

### Requirement: 渠道连接测试

系统 SHALL 支持对单个渠道执行连接测试。测试通过向渠道 Base URL 发起模型列表请求验证连通性与密钥有效性，并展示测试结果。

#### Scenario: 测试成功的渠道

- **WHEN** 用户对渠道发起连接测试且渠道返回正常响应
- **THEN** 界面展示测试成功及渠道可用的模型数量

#### Scenario: 测试失败的渠道

- **WHEN** 用户对渠道发起连接测试且渠道返回错误（网络错误、401 等）
- **THEN** 界面展示测试失败及失败原因

### Requirement: 渠道状态记录

系统 SHALL 记录渠道的可用状态（在线/离线/冷却）与最近一次错误信息，供 GUI 展示与故障排查。

#### Scenario: 渠道请求失败

- **WHEN** 代理请求转发到某渠道并失败
- **THEN** 系统更新该渠道的最近错误信息与状态

#### Scenario: 展示渠道状态

- **WHEN** 用户在渠道管理页查看渠道列表
- **THEN** 列表展示每个渠道当前状态、最近错误与最近成功时间
